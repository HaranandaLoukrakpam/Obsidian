# Context-Free Grammar (CFG)

## Definition

A **Context-Free Grammar (CFG)** is a formal grammar used to describe the syntax of languages, especially programming languages. It consists of a set of production rules that define how strings in a [[Context-Free Language]] can be generated.

A CFG is more powerful than a [[Regular Grammar]] because it can describe **recursive** and **nested structures**, such as balanced parentheses and arithmetic expressions.

Every [[Context-Free Language]] can be generated by a Context-Free Grammar and recognized by a [[Pushdown Automata]].

---

## Key Idea

A Context-Free Grammar starts with a **start symbol** and repeatedly applies **production rules** to generate valid strings in a language.

Unlike [[Regular Grammar]], CFGs can generate languages that require recursive structures.

---

## Characteristics

- Generates [[Context-Free Language|Context-Free Languages]].
- Uses production rules.
- Supports recursion.
- Handles nested structures.
- Widely used in compiler design.
- More powerful than [[Regular Grammar]].
- Less powerful than unrestricted grammars.

---

## Formal Definition

A Context-Free Grammar is represented as a **4-tuple**:

\[
G = (V,\Sigma,P,S)
\]

Where:

| Symbol | Meaning |
|--------|---------|
| **V** | Finite set of non-terminal symbols |
| **Σ (Sigma)** | Finite set of terminal symbols |
| **P** | Set of production rules |
| **S** | Start symbol |

---

## Components of a CFG

### [[Terminal]]

A symbol that appears in the final generated string and cannot be replaced further.

Examples:

```
a
b
0
1
+
*
(
)
```

---

### [[Non-Terminal]]

A variable that can be replaced using production rules.

Examples:

```
S
A
B
E
T
F
```

---

### [[Production Rule]]

A rule that specifies how a non-terminal can be replaced.

General form:

```
A → α
```

Where:

- **A** is a non-terminal.
- **α** is a combination of terminals and/or non-terminals.

---

### [[Start Symbol]]

The non-terminal from which string generation begins.

Usually:

```
S
```

---

## Example 1

Grammar:

```
S → aSb
S → ε
```

Generated strings:

```
ε
ab
aabb
aaabbb
aaaabbbb
```

Language:

```
L = { aⁿbⁿ | n ≥ 0 }
```

---

## Example 2

Grammar:

```
S → aS
S → b
```

Generated strings:

```
b
ab
aab
aaab
```

Language:

```
L = { aⁿb | n ≥ 0 }
```

---

## Derivation

A **derivation** is the process of applying production rules to generate a string.

---

### Leftmost Derivation

Always replace the **leftmost non-terminal** first.

Example:

Grammar

```
S → aSb
S → ε
```

Generate:

```
aabb
```

Steps:

```
S
⇒ aSb
⇒ aaSbb
⇒ aaεbb
⇒ aabb
```

---

### Rightmost Derivation

Always replace the **rightmost non-terminal** first.

Example:

```
S
⇒ aSb
⇒ aaSbb
⇒ aaεbb
⇒ aabb
```

---

## Parse Tree

A **Parse Tree** (or **Derivation Tree**) is a tree representation showing how a string is generated using a CFG.

Example:

Grammar

```
S → aSb
S → ε
```

String:

```
ab
```

Parse tree:

```
      S
    / | \
   a  S  b
      |
      ε
```

---

## Ambiguous Grammar

A grammar is **ambiguous** if at least one string can have **more than one parse tree** or **more than one leftmost/rightmost derivation**.

Example:

```
E → E + E
E → E * E
E → id
```

Expression:

```
id + id * id
```

This expression can have multiple parse trees.

---

## Unambiguous Grammar

A grammar is **unambiguous** if every valid string has exactly **one parse tree**.

---

## Types of Production Rules

### Recursive Production

Example:

```
S → aS
```

Allows unlimited repetition.

---

### Base Production

Terminates recursion.

Example:

```
S → ε
```

or

```
S → b
```

## Advantages

- Handles recursive structures.
- Supports nested expressions.
- Easy to describe programming language syntax.
- More expressive than regular grammars.
- Forms the basis of parser construction.

---

## Limitations

- Cannot describe every language.
- Ambiguous grammars may require rewriting.
- Less powerful than unrestricted grammars.
- Some CFGs are difficult to parse efficiently.

---

## Context-Free Grammar vs Regular Grammar

| Context-Free Grammar | Regular Grammar |
|----------------------|-----------------|
| Generates [[Context-Free Language|Context-Free Languages]] | Generates [[Regular Language|Regular Languages]] |
| Recognized by [[Pushdown Automata]] | Recognized by [[Finite Automata]] |
| Supports recursion | Limited recursion |
| Can generate nested structures | Cannot generate nested structures |
| More expressive | Less expressive |

---

## Context-Free Grammar vs Finite Automata

| Context-Free Grammar | Finite Automata |
|----------------------|-----------------|
| Generates languages | Recognizes languages |
| Uses production rules | Uses state transitions |
| Supports recursion | No memory |
| Equivalent to [[Pushdown Automata]] | Equivalent to [[Regular Expression]] |

# Pushdown Automata (PDA) and Context-Free Languages (CFL)

## Definition

A **Pushdown Automaton (PDA)** is a mathematical model of computation that extends a [[Finite Automata]] by adding a **stack** as auxiliary memory. The stack enables a PDA to recognize languages that require remembering an arbitrary amount of information, such as matching parentheses or balanced symbols.

A **Context-Free Language (CFL)** is a language that can be generated by a [[Context-Free Grammar (CFG)]] and recognized by a [[Pushdown Automata]].

---

# Pushdown Automata (PDA)

## Definition

A **Pushdown Automaton (PDA)** is an abstract machine that consists of:

- A finite set of states
- An input tape
- A stack
- A transition function

The stack allows the PDA to **push**, **pop**, and **peek** symbols, making it more powerful than a [[Finite Automata]].

---

## Key Idea

A PDA processes an input string one symbol at a time while using a **stack** to remember information.

Unlike a [[Finite Automata]], which has no memory, a PDA can recognize nested and recursive structures.

---

## Characteristics

- Finite number of states.
- Uses a stack as memory.
- Reads one input symbol at a time.
- Can push and pop stack symbols.
- Recognizes [[Context-Free Language|Context-Free Languages]].
- More powerful than [[Finite Automata]] but less powerful than a [[Turing Machine]].

---

## Components of a PDA

A Pushdown Automaton is formally represented as a **7-tuple**:

\[
M=(Q,\Sigma,\Gamma,\delta,q_0,Z_0,F)
\]

Where:

| Symbol | Meaning |
|--------|---------|
| **Q** | Finite set of states |
| **Σ (Sigma)** | Input alphabet |
| **Γ (Gamma)** | Stack alphabet |
| **δ (Delta)** | Transition function |
| **q₀** | Initial state |
| **Z₀** | Initial stack symbol |
| **F** | Set of accepting states |

---

## Stack Operations

### Push

Adds a symbol to the top of the stack.

Example:

```
Stack

Top
----
A
B
C
```

Push D

```
Top
----
D
A
B
C
```

---

### Pop

Removes the top symbol.

```
Before

Top
----
D
A
B
C
```

After Pop

```
Top
----
A
B
C
```

---

### Peek (Top)

Reads the top symbol without removing it.

---

## Working of a PDA

1. Start in the initial state.
2. Read one input symbol.
3. Check the top of the stack.
4. Push or pop symbols according to the transition function.
5. Continue until the input is exhausted.
6. Accept if the acceptance condition is satisfied.

---

## Acceptance of PDA

A PDA can accept a string in two ways:

### Acceptance by Final State

The machine accepts when:

- Input is completely read.
- Current state is a final state.

---

### Acceptance by Empty Stack

The machine accepts when:

- Input is completely processed.
- Stack becomes empty.

---

## Types of PDA

### [[Deterministic Pushdown Automata (DPDA)]]

- Only one valid transition for each input and stack symbol.
- Used in deterministic parsing.

---

### [[Non-Deterministic Pushdown Automata (NPDA)]]

- Multiple transitions may exist.
- More powerful than DPDA in language recognition.
- Every [[Context-Free Language]] can be recognized by an NPDA.

---

## Example

Language:

```
L = { aⁿbⁿ | n ≥ 1 }
```

Accepted Strings:

```
ab
aabb
aaabbb
aaaabbbb
```

Rejected Strings:

```
abb
aaabb
aabbbb
abab
```

Working:

- Push every **a** onto the stack.
- Pop one symbol for each **b**.
- Accept if the input ends and the stack is empty.

---

## Applications of PDA

- Compiler parsing
- Syntax analysis
- Expression evaluation
- XML/HTML tag matching
- Parentheses balancing
- Programming language parsing

# Context-Free Language (CFL)

## Definition

A **Context-Free Language (CFL)** is a language generated by a [[Context-Free Grammar (CFG)]]. Every Context-Free Language can be recognized by a [[Pushdown Automata]].

CFLs are widely used to describe the syntax of programming languages and natural languages.

---

## Context-Free Grammar (CFG)

A CFG consists of production rules of the form:

```
A → α
```

Where:

- **A** is a non-terminal.
- **α** is a combination of terminals and non-terminals.

Example:

```
S → aSb
S → ε
```

Generates:

```
ε
ab
aabb
aaabbb
aaaabbbb
```

---

## Characteristics of CFL

- Generated using CFG.
- Recognized by PDA.
- Supports recursive structures.
- Allows nested expressions.
- More powerful than [[Regular Language|Regular Languages]].

---

## Examples of CFLs

### Balanced Parentheses

```
()
(())
((()))
```

---

### Equal Number of a's and b's

```
ab
aabb
aaabbb
```

---

### Arithmetic Expressions

```
a+b
(a+b)*c
a*(b+c)
```

---

### Programming Language Syntax

Examples:

- If statements
- Loops
- Function definitions
- Nested blocks

---

## Regular Language vs Context-Free Language

| Regular Language | Context-Free Language |
|------------------|-----------------------|
| Recognized by [[Finite Automata]] | Recognized by [[Pushdown Automata]] |
| Generated by [[Regular Expression]] | Generated by [[Context-Free Grammar (CFG)]] |
| No memory | Uses a stack |
| Cannot handle nested structures | Handles nested structures |
| Less powerful | More powerful |

---

## PDA vs Finite Automata

| Pushdown Automata | Finite Automata |
|-------------------|-----------------|
| Uses a stack | No auxiliary memory |
| Recognizes Context-Free Languages | Recognizes Regular Languages |
| Supports recursion | No recursion support |
| Can recognize balanced parentheses | Cannot recognize balanced parentheses |

---

## PDA vs Turing Machine

| Pushdown Automata | Turing Machine |
|-------------------|----------------|
| Stack memory | Infinite tape memory |
| Recognizes CFLs | Recognizes recursively enumerable languages |
| Less powerful | More powerful |
| Used mainly for parsing | Used for general computation |

---

## Advantages

- Supports recursive language structures.
- Recognizes nested patterns.
- Essential in compiler design.
- Models programming language syntax.
- More powerful than finite automata.

---

## Limitations

- Cannot recognize all languages.
- Less powerful than a [[Turing Machine]].
- Limited by stack-based memory.

---

## Real-World Applications

- Compiler syntax analysis
- Parsing programming languages
- XML and HTML validation
- Expression parsing
- Mathematical formula validation
- Natural language processing (grammar parsing)

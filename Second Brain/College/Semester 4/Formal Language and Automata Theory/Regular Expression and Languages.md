# Regular Expressions and Regular Languages

## Definition

A **Regular Expression (Regex or RE)** is a formal notation used to describe patterns in strings. It defines a set of strings known as a **Regular Language**.

A **Regular Language** is a language that can be recognized by a [[Finite Automata]] or generated using a [[Regular Expression]].

Regular expressions are widely used in compiler design, text processing, pattern matching, search operations, and input validation.

---

# Regular Expressions (RE)

## Definition

A **Regular Expression** is a sequence of symbols and operators that specifies a search pattern or language over a given alphabet.

For an alphabet:

```
Σ = {a, b}
```

Examples of regular expressions:

```
a
b
ab
a*
(a+b)
(ab)*
```

Each regular expression represents a set of valid strings.

---

## Basic Symbols

### Alphabet (Σ)

A finite set of valid input symbols.

Example:

```
Σ = {0,1}
```

or

```
Σ = {a,b}
```

---

### Empty String (ε)

Represents a string containing **no characters**.

Length:

```
|ε| = 0
```

---

### Empty Set (∅)

Represents **no possible strings**.

Language:

```
L = ∅
```

---

## Regular Expression Operators

### Concatenation

Combines two expressions.

Example:

```
ab
```

Matches:

```
ab
```

---

### Union ( + or | )

Represents logical OR.

```
a+b
```

Matches:

```
a
b
```

---

### Kleene Star (*)

Represents **zero or more** occurrences.

```
a*
```

Matches:

```
ε
a
aa
aaa
aaaa
...
```

---

### Kleene Plus (+)

Represents **one or more** occurrences.

```
a+
```

Matches:

```
a
aa
aaa
...
```

Equivalent to:

```
aa*
```

---

### Optional (?)

Represents **zero or one** occurrence.

```
a?
```

Matches:

```
ε
a
```

---

### Parentheses ( )

Used for grouping expressions.

Example:

```
(ab)*
```

Matches:

```
ε
ab
abab
ababab
...
```

---

## Examples of Regular Expressions

### Strings containing only a's

```
a*
```

Language:

```
{ ε, a, aa, aaa, ... }
```

---

### Strings ending with b

```
(a+b)*b
```

Examples:

```
b
ab
aab
bb
abab
```

---

### Strings starting with a

```
a(a+b)*
```

Examples:


---

### Binary Strings

Alphabet:

```
Σ={0,1}
```

Expression:

```
(0+1)*
```

Generates every binary string.

# Regular Languages

## Definition

A **Regular Language** is a language that can be:

- Generated by a [[Regular Expression]]
- Recognized by a [[Finite Automata]]
- Generated by a [[Regular Grammar]]

---

## Characteristics

- Finite memory requirement.
- Recognized using DFA or NFA.
- No recursion beyond regular structures.
- Cannot represent nested patterns.

---

## Examples

### Language 1

```
L = {a, aa, aaa, ...}
```

Regular Expression:

```
a+
```

---

### Language 2

Strings over `{0,1}` ending in **1**.

Regular Expression:

```
(0+1)*1
```

Examples:

```
1
01
101
111
```

---

### Language 3

Strings beginning with **a**.

Regular Expression:

```
a(a+b)*
```

---

### Language 4

All binary strings.

```
(0+1)*
```

---

## Properties of Regular Languages

Regular languages are closed under:

### Union

```
L₁ ∪ L₂
```

---

### Concatenation

```
L₁L₂
```

---

### Kleene Star

```
L*
```

---

### Complement

```
Σ* − L
```

---

### Intersection

```
L₁ ∩ L₂
```

---

### Difference

```
L₁ − L₂
```

---

### Reversal

Reverse every string in the language.

---

## Regular Grammar

A grammar that generates a regular language.

Example:

```
S → aS
S → bS
S → ε
```

Generates:

```
ε
a
b
aa
ab
ba
bb
...
```

---

## Regular Expression vs Regular Language

| Regular Expression | Regular Language |
|--------------------|------------------|
| Describes a pattern | Set of strings described by the pattern |
| Formal notation | Collection of accepted strings |
| Used to generate languages | Recognized by automata |

---

## Regular Language vs Context-Free Language

| Regular Language | Context-Free Language |
|------------------|-----------------------|
| Recognized by [[Finite Automata]] | Recognized by [[Pushdown Automata]] |
| Generated by [[Regular Expression]] | Generated by [[Context-Free Grammar (CFG)]] |
| No stack memory | Uses stack memory |
| Cannot recognize nested structures | Recognizes nested structures |
| Less expressive | More expressive |

---

## Finite Automata and Regular Expressions

According to **Kleene's Theorem**:

- Every [[Regular Expression]] has an equivalent [[Finite Automata]].
- Every [[Finite Automata]] has an equivalent [[Regular Expression]].

Thus,

```
Regular Expression
        ⇄
Finite Automata
```

Both recognize exactly the same class of languages: **Regular Languages**.

---

## Advantages

- Simple and efficient.
- Fast pattern matching.
- Easy to implement.
- Widely supported in programming languages.
- Fundamental to compiler construction.

---

## Limitations

- Cannot recognize nested or recursive structures.
- Cannot count arbitrary numbers of symbols.
- Less powerful than [[Context-Free Grammar (CFG)]].
- Cannot recognize all programming language syntax.
